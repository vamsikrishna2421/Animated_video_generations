Episode 55 of AI From Scratch: build your own MCP server (Season 6, a screen tutorial)
MCP (the Model Context Protocol) is a standard plug for AI apps: put a tool in a server once, and any app that speaks MCP can ask what tools it has and use them. Anthropic released it as an open standard (Nov 2024); OpenAI added it to its Agents SDK (Mar 2025).
1. The server: 12 lines with the official Python SDK. One function, get_order(order_id), a one-line description, and its input.
2. The bot asks the server what tools it has (list_tools) and builds its tool list from the answer. Nothing about orders is written in the bot.
3. Our test, a made-up shop, 10 customers, a small free AI on our computer: 1 right of 10. The AI sent the order number as a number (4388); the server's input said text (order_id: str) and refused it. The 1 right: the one time the AI sent "4502" as text. Our client code had shown the AI the input's name, not its type.
4. The fix: accept a number or text (order_id: str | int, plus one sentence in the description) and show the AI the types. WhatsApp bot: 1 → 10 of 10. Website bot: 0 → 7 of 10; the other 3, the AI wrote broken JSON ({"order_id": 4417"}), so no lookup happened.
5. Then one change on the server (order 4417: refund approved): the WhatsApp bot answered "Your refund of Rs 1,299 has been approved", with no change to the bot.
Which do you need? One app: a plain tool (EP54). Two or more apps: a server.

=== PINNED_COMMENT ===
The server, runnable (Python 3.10+; pip install mcp==2.3.0 openai). Save as orders_server.py:
import json
from mcp.server.mcpserver import MCPServer
ORDERS = {"4417": {"item": "Bluetooth earphones", "refund": "Rs 1,299 approved; 5-7 working days"}}
mcp = MCPServer("shop-orders")
@mcp.tool()
def get_order(order_id: str | int) -> dict:
    """Look up one order: item, status and refund. order_id: the order number."""
    return ORDERS.get(str(order_id).strip().lstrip("#"), {"error": "no such order"})
if __name__ == "__main__":
    mcp.run("stdio")
The bot is in the next pinned comment. Run: python3 bot.py (it starts the server itself).

=== PINNED_COMMENT_2 ===
The bot, bot.py (any OpenAI-compatible chat API, a local llama.cpp server included):
import asyncio, json, re, sys
from openai import OpenAI
from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client
llm = OpenAI()  # key in OPENAI_API_KEY (or base_url=... for a local server)
MODEL = "your-model-name"
def ask(msgs): return llm.chat.completions.create(model=MODEL, messages=msgs).choices[0].message.content
def kind(p): return " or ".join(x["type"] for x in p["anyOf"]) if "anyOf" in p else p.get("type", "")
async def main(q):
    async with stdio_client(StdioServerParameters(command=sys.executable, args=["orders_server.py"])) as (r, w), ClientSession(r, w) as s:
        await s.initialize()
        tools = (await s.list_tools()).tools  # ask the server what it has
        desc = "\n".join(f"- {t.name}({', '.join(f'{k}: {kind(v)}' for k, v in t.input_schema['properties'].items())}): {t.description}" for t in tools)
        msgs = [{"role": "system", "content": "You reply to a shop's customers. Tools:\n" + desc + '\nTo use one, reply with only {"tool": "<name>", "args": {...}}. Then answer only from the result.'},
                {"role": "user", "content": q}]
        reply = ask(msgs)
        m = re.search(r"\{.*\}", reply, re.S)
        try: call = json.loads(m[0]) if m else None
        except ValueError: call = None  # broken JSON from a small AI: no call
        if call:
            res = await s.call_tool(call["tool"], call.get("args", {}))
            msgs += [{"role": "assistant", "content": reply}, {"role": "user", "content": "Tool result: " + res.content[0].text}]
            reply = ask(msgs)
        print(reply)
asyncio.run(main("Where is my refund? Order 4417."))
How we tested (Nov 17, 2026): a made-up shop (its prompt called it "Kiran Mobiles"; no real shop), 10 orders we wrote, Qwen2.5-7B-Instruct (4-bit) on llama.cpp on our computer, temperature 0.2, one fresh chat per question, every reply read by hand. This short version was checked end to end against a stand-in chat server.
